# 02 — 선택 조건 3종 추가

## Outcome

의뢰자가 풍량 의뢰서의 해석조건에 공간 압력, 열교환기, 필터를 입력할 수 있다. 각 조건은 사용 여부를 정하고, 입력값은 보존되며, Case 열로 비교된다. 열교환기 사양은 샘플 Catalog에 있는 조합만 허용한다.

## Blockers

01. 01이 만든 의뢰서, 운전 조건, Case, 제출 조건 위에 붙는 작업이다.

## Acceptance criteria

- [x] 공간 압력은 값(입구·출구) 또는 "없음"을 선택해야 하고, 선택하지 않은 빈 상태로는 제출할 수 없다.
- [x] 열교환기 사양(유형, 관 직경 또는 채널 폭, Fin type, 열 수, FPI)이 샘플 Catalog에 없는 조합이면 제출할 수 없다. "열교환기 없음"을 고르면 사양을 요구하지 않는다. 열교환기 조건 패키지를 여러 개 만들 수 있다.
- [x] 필터는 "제품에 필터가 있음"을 체크한 경우에만 필터 패키지, 물리적 필터, 측정점(유속·압력손실, 1개 이상)을 요구한다. 체크하지 않으면 요구하지 않고 Case에 "없음"으로 보인다.
- [x] "없음"을 선택하거나 사용 체크를 해제해도 입력했던 값은 지워지지 않고, 다시 켜면 복원된다. Case와 최종 검토에는 "없음"으로 보인다.
- [x] Case에 공간 압력, 열교환기, 필터 열이 추가되고, 활성 열을 모두 선택해야 제출할 수 있다. 활성 조건까지 모두 같은 Case는 만들 수 없고, 입력한 모든 패키지는 최소 한 Case에서 쓰인다.
- [x] 조건 패키지를 추가·삭제·수정하면 사라진 선택이 비워지고 Case 재확인이 필요하다. 필터 안의 물리적 필터나 측정점을 추가해도 새 Case가 생기지 않는다.
- [x] 같은 내용의 조건 패키지가 중복되면 제출할 수 없다.
- [x] 매핑에 없는 조건(공간 온도, 취출 조건 등)과 설치 조건은 화면에 나타나지 않는다.

## Constraints

- 설치 조건은 표시하지 않는다(명세의 범위 밖).
- 열교환기 Catalog 임시 샘플 데이터는 이 작업에서 만든다(01에서 옮겨 왔다).
- 열교환기 Catalog는 임시 샘플이다. 검증 규칙은 Catalog 내용이 바뀌어도 그대로 동작해야 한다.
- 조건 규칙의 세부는 [해석의뢰 업무정의서](../../../../해석의뢰%20업무정의서.md)의 5.1(공통 규칙), 5.3.2(공간 압력), 5.3.4(열교환기), 5.3.5(필터), 6장을 따른다.
- 화면 구성은 [docs/decisions/ui-composition.md](../../../decisions/ui-composition.md)를 따른다.

## Verification

- 단위 테스트: 공간 압력 필수·없음 규칙, Catalog 조합 검증, 필터 사용 여부와 측정점 최소 1개 규칙, 값 보존과 복원, Case 열 추가와 중복·누락 규칙, 패키지 중복 검사가 기대한 결과를 낸다.
- E2E: 선택 조건을 모두 입력한 의뢰를 제출하면 성공하고, Catalog에 없는 열교환기 조합이나 빈 공간 압력은 제출이 막힌다.

- Revision: 열교환기 선택지를 Catalog에서 단계별로 좁혀 보여 주므로 화면에서는 Catalog에 없는 조합을 만들 수 없다. Catalog 밖 조합 차단은 단위 테스트로 검증했다(이전 저장 데이터나 Catalog 변경 대비). 선택 조건이 없던 이전 형식 저장본은 불러올 때 빈 선택 조건으로 채운다. 해석조건 단계의 이름을 "운전 조건"에서 "해석조건"으로 바꿨다.
