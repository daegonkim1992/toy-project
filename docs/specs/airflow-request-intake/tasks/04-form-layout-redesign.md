# 04 — 승인된 시안으로 의뢰서 화면 개편

## Outcome

의뢰자가 작성하는 의뢰서 6단계 화면이 승인된 시안(`prototype.html`)과 같은 구성으로 바뀐다. 반복 항목(해석 제품, 운전 조건, 선택 조건 패키지)은 표 한 줄씩, 선택 조건의 사용 여부는 각 조건 제목 줄의 있음·없음으로 고르고, Case는 선택지가 하나뿐인 조건만 있으면 형상 × 운전 조건 격자로 고른다. 단계 버튼에는 진행 상태가 늘 보이고, 이전·다음·제출과 의뢰 취소는 화면 하단에 고정된다. 의뢰서의 동작 규칙(제출 조건, 상태 흐름, 조회 범위)은 바뀌지 않는다.

## Blockers

None. 01~03이 완료되어 바꿀 화면과 규칙이 모두 있다.

## Acceptance criteria

- [x] 단계 버튼에 단계별 상태가 표시된다: 빠진 항목이 없으면 ✓, 있으면 남은 개수, 의뢰 대상을 확정하기 전에는 "확정 필요", Case는 구성 확인만 남았으면 "확인 필요". 입력하면 바로 바뀐다.
- [x] 이전·다음(다음 단계 이름 포함)과 의뢰 취소가 화면 하단에 고정되고, 최종 검토 단계에서는 다음 대신 제출(보완 필요 상태에서는 재제출) 버튼이 나온다. 의뢰 대상을 확정하기 전에는 다른 단계로 이동할 수 없다.
- [x] 의뢰 내용: 의뢰자 정보는 한 줄 요약으로 보이고 "수정"을 누르면 입력 칸이 펼쳐진다. 의뢰 개요의 짧은 칸은 2열로, 배경과 확인 내용은 넓은 화면에서 나란히 보인다. 결과 활용 목적은 "선택 항목"을 펼쳐야 보인다.
- [x] 해석 제품: 형상, 구분, 도면번호, Base 대비 차이가 한 표에 보이고 Base가 첫 행이다. 비교 제품은 행 단위로 추가·삭제한다.
- [x] 해석조건: 운전 조건은 운전 대안마다 한 행이고, 팬별 설정이면 그 행 아래에 팬별 위치와 회전수가 펼쳐진다. 풍량을 입력해야 풍량 활용을 고를 수 있다.
- [x] 해석조건: 공간 압력, 열교환기, 필터는 제목 줄의 있음·없음으로 고르고, 있음일 때만 그 자리에 입력 표가 펼쳐진다. 공간 압력과 열교환기를 아직 고르지 않았으면 "선택 필요"로 표시된다. 필터는 패키지, 물리적 필터, 측정점을 표에서 추가·삭제할 수 있다.
- [x] Case: 운전 조건 외의 활성 조건이 모두 선택지 하나뿐이면 형상 × 운전 조건 체크 격자로 고르고, 하나뿐인 선택지는 모든 Case에 자동으로 들어간다. 선택지가 둘 이상인 조건이 있으면 행 단위 표로 고른다. 두 방식 모두 전부 선택(전부 조합) 버튼이 있다.
- [x] 아무 조합도 고르지 않은 형상은 "형상 N의 조합을 하나 이상 골라야 합니다"로 안내된다.
- [x] 최종 검토: 단계별 요약 카드에 그 단계의 빠진 항목과 해당 단계로 이동하는 수정 링크가 있다.
- [x] 긴 안내 문구는 제목 옆 도움말 아이콘을 눌러야 보인다.
- [x] 01~03의 동작(제출 조건, 보완 요청·재제출·접수·취소 흐름, 조회 범위)이 그대로 통과한다.

## Constraints

- 화면 배치는 [prototype.html](../prototype.html)과 [docs/decisions/request-form-layout.md](../../../decisions/request-form-layout.md)를 따른다. 시안의 예시 데이터와 샘플 사용자는 계약이 아니다.
- 일반 UI 구성 요소는 [docs/decisions/ui-composition.md](../../../decisions/ui-composition.md)를 따른다.
- 관리자·담당자의 조회 화면과 홈 화면은 이 작업에서 바꾸지 않는다.

## Verification

- 단위 테스트: Case 격자 사용 조건, 격자 칸 선택·해제와 하나뿐인 선택지 자동 채움, 전부 조합 생성, 조합이 없는 형상 안내 문구가 기대한 결과를 낸다. 기존 단위 테스트가 모두 통과한다.
- E2E: 새 화면으로 작성→제출, 제출 차단, 선택 조건 입력→Case→제출, 보완 요청→재제출→접수, 취소 흐름이 통과한다.
