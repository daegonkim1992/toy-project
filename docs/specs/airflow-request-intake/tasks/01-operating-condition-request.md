# 01 — 운전 조건만으로 풍량 의뢰서 작성·제출

## Outcome

의뢰자가 샘플 사용자로 전환해 들어와, 단계별 화면(의뢰 대상 → 의뢰 내용 → 해석 제품 → 운전 조건 → Case → 최종 검토)으로 풍량 해석 의뢰서를 작성하고, 저장해 두었다가 이어 쓰고, 제출 조건을 충족하면 제출한다. 제출하면 의뢰가 "검토 중" 상태가 되고 revision 1과 상태 변화 이력이 남는다. 의뢰자는 자기 의뢰 목록과 같은 부서 사용자의 의뢰(조회만)를 볼 수 있다. 임시 샘플 기준 데이터(제품 분류, PMS 프로젝트)가 들어 있다. 열교환기 Catalog 샘플은 처음 쓰이는 02에서 만든다. 공간 압력, 열교환기, 필터는 이 작업에 없으며 Case는 형상과 운전 조건 열로만 구성한다.

## Blockers

None.

## Acceptance criteria

- [x] 화면에서 샘플 사용자(의뢰자 2명 이상 중 소속 부서가 같은 사용자가 있고 다른 부서 사용자 1명 이상, 해석관리자 1명 이상, 해석담당자 1명 이상)를 전환할 수 있다.
- [x] 의뢰자가 단계별 화면으로 풍량 의뢰서를 작성할 수 있고, 저장한 작성 중 의뢰를 브라우저를 닫았다 다시 열어도 같은 의뢰자가 이어 쓸 수 있다.
- [x] 의뢰 대상 확정 시 의뢰번호가 `CFD-YYYYMMDD-NNN` 형식으로 발급되고, 같은 날 두 번째 의뢰는 다른 번호를 받는다.
- [x] 제품 분류는 샘플 데이터에 등록된 조합에서만 고를 수 있다. 해석 범위, 운전 구분 같은 조건부 항목은 해당 조합에서만 나타난다.
- [x] 의뢰 유형이 개발 프로젝트이면 제품 사업부에 해당하는 PMS 프로젝트가 필수이고, 고르면 개발 등급과 NPI 단계가 필수가 된다. 다른 유형에서는 요구하지 않는다.
- [x] 희망 완료일이 의뢰 요청일보다 앞서면 제출할 수 없다.
- [x] Base 제품이 정확히 1개이고, 모든 제품에 형식에 맞고 중복되지 않는 도면번호가 있고, 비교 제품마다 Base 대비 차이가 있어야 제출할 수 있다.
- [x] 운전 조건: 팬 개수는 1~10이고, "팬별 설정"이면 팬마다 회전수와 팬 위치를 받는다. 풍량을 입력하면 활용 목적이 필수이고, 회전수 없이 풍량만 있고 활용 목적이 "참고 정보"인 조합과 회전수도 풍량도 없는 운전 조건은 제출할 수 없다. 운전 대안은 운전 조건 패키지로, 동시에 도는 여러 팬은 한 패키지 안의 팬으로 입력한다.
- [x] Case: 형상마다 기본 1행이 생기고, 형상과 운전 열을 모두 선택해야 하며, 같은 Case 중복은 만들 수 없고, 입력한 형상과 운전 패키지는 최소 한 Case에서 쓰인다. 제품이나 조건이 바뀌면 사라진 선택은 비워지고 Case 재확인이 필요하다.
- [x] 모든 자유 입력은 200자를 넘을 수 없다.
- [x] 제출 조건을 충족하지 못하면 제출이 막히고 최종 검토 단계에서 미충족 위치가 보인다.
- [x] 제출하면 상태가 "검토 중"이 되고, revision 1과 이력(수행자, 이전·이후 상태, 시각)이 남으며, 검토 중에는 의뢰서 내용을 수정할 수 없다.
- [x] 의뢰자는 자기 의뢰와 소속 부서가 같은 사용자의 의뢰를 볼 수 있고, 같은 부서 의뢰에서는 수정·제출 메뉴가 보이지 않으며, 다른 사용자의 작성 중 의뢰는 보이지 않는다.

## Constraints

- 단계별 작성은 확정된 결정이다(명세의 "확정한 제약과 근거").
- 해석유형은 풍량 하나로 고정한다. 해석유형 선택 화면은 만들지 않는다.
- 풍량 입력 단위는 임시로 하나를 고정해 라벨에 표시한다(명세의 가정).
- 기준 데이터와 사용자는 임시 샘플이다. 실제 파일과 로그인으로 바꿔도 의뢰서 규칙이 달라지지 않도록 규칙이 데이터 내용에 하드코딩되어서는 안 된다.
- 화면 구성은 [docs/decisions/ui-composition.md](../../../decisions/ui-composition.md)를 따른다. 이 문서가 일반 UI 구성, 공통 shell, 상태 표현을 정한다.
- 필드별 규칙, 매핑, 제출 조건의 세부는 [해석의뢰 업무정의서](../../../../해석의뢰%20업무정의서.md)의 4장, 5.3.1(운전 조건), 6장, 8장을 따른다.

## Verification

- 단위 테스트: 제출 조건(제품·도면번호·비교 차이, PMS·개발 등급, 희망 완료일, 200자), 운전 조건 적용 규칙(회전수·풍량·활용 목적 조합), Case 규칙(중복, 누락, 재확인), 의뢰번호 발급, 의뢰자 조회 범위가 기대한 결과를 낸다.
- E2E: 대표 의뢰(기존 팬 Base와 변경 팬 비교 제품)를 작성하고 저장한 뒤 새로 열어 이어 쓰고 제출하면, 상태가 "검토 중"이고 이력에 제출이 남는다. 제출 조건을 어긴 의뢰는 제출이 막히고 위치가 보인다.
